# Security policy

## Supported versions

| Version | Security fixes |
| --- | --- |
| Latest 0.5.x patch release | Supported |
| Earlier release lines | Not supported |

Use the latest available 0.5.x patch release when reporting or verifying a fix.

## Report privately

Report suspected vulnerabilities through this repository's **Security →
Advisories → Report a vulnerability** page, using GitHub private vulnerability
reporting. Do not open a public issue or pull request containing exploit details.

Include the affected version and component, configuration needed to reproduce,
expected and observed behavior, a minimal reproducer, and the potential impact.
Remove credentials, key material, personal data, and production data from reports.

## Response expectations

Maintainers aim to acknowledge reports within two business days and provide an
initial triage update within seven days. These are response targets, not a
promise of a fix by a particular date. Investigation and remediation depend on
severity, reproducibility, and affected dependencies. Follow up in the private
report if an acknowledgement is delayed.

Maintainers coordinate remediation and public disclosure with the reporter in
the private report. Reporter credit is optional; request anonymity if preferred.

See [the security model](docs/SECURITY.md) for trust boundaries and report scope.
